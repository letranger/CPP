2. 比賽時間估算

2.1. 先計算 O(N)，再看題目給的 N 範圍，例如：

complexity 為\[N^2\]，\[1<=N<=3000\]，則最糟的狀況為\[3000^2=9000000\]

  • < 100 萬: 一定會過
  • 100~1000 萬: 應該會過
  • 1000 ~ 5000 萬: 有機會
  • > 5000 萬: 不可能過

2.2. 反向推論，也可以由 N 的範園來回推應該要寫出\[O(N^2)\]或是\[O(N)\]的解決

5. vector 少用的 operator: find, insert, erase

這些動作都會讓 vector 去逐一改變所有元素的位置，速度會很慢，複雜度為 O(N) 例如，若有某題要求做刪除 vector 中的 N 個元素，其複雜度就會變成\[O(N^2)\] 比較好的做法是：開一個新的 vector，再逐一把需要的元素放到新的 vector 中 find 也是 O(N)，如果只是要找一次，可以自己寫 for，如果要找很多次，可以先 SORT 再去做 binary

8. SORT

intro sort: \[O(nlogn)\]quick sort+某些功能，使其最差狀況不那麼差 預設由小排到大 sort(aryt0, arytn); // [0, n) 左閉右開

  • 不要用 operator<，儘量用 function

sort(ary, arytn, comp);

8.1. comp

有兩類，一種用在 container

  • example
1: sort(v.begin, v.end());
2: // 由大排到小
3: bool comp(int p, int q) {
4:     if (p > q)
5:         return true;
6:     return false;
7: }

function comp 的撰寫要非常小心，要保證 p,q 兩者反過來後絕對不會 return true，否則 SORT 會出現 run time error，典型的例子是: 

1: sort(v.begin, v.end());
2: // 由大排到小
3: bool comp(int p, int q) {
4:     if (p >= q) // p, q對調後有可能也成立
5:         return true;
6:     return false;
7: }

8.2. stable / unstable

sort 本身為 unstable，若需要 stable 則可 stablesort()

8.3. 對一份 ary 做不同版本的 sort

陣列 0 1 2 3 4
A 3 7 5 6 4
P(原始) 0 1 2 3 4
P(排序) 0 4 2 3 1

如此就可以有很多種 P，可以進行不同的 sort，如由大到小、由小到大….. 此時的 comp 要寫為: 

1: bool comp(int p, int q) {
2:     if (A[p] > A[q]) 
3:         return true;
4:     return false;
5: }

若 A 的原始順序為排隊的先後，A的元素代表等級，如果讓等級高的人先得到服務，等級一樣的人則依排隊順序，則其 comp 寫法為： 

1: bool comp(int p, int q) {
2:     if (A[p] != A[q])
3:         return A[p] > A[q];
4:     return p < q;
5: }

10. lowerbound

10.1. 寫法

lowerbound(aryt0, arytn, k): 以 binary search 找到第一個>=k 的元素

10.2. 先決條件

  • 要有 operator<
  • 要能 random access，使其複雜度為\[log_2n\]
  • partitioned by k: 要能找到一個 i，可以把 ary 分切成兩半(即 sorted) 即，存在 i, 0<=i<n, 對 j<i 可找到 ary[j]<k，對 j>=i，可找到 ary[j]>=k

10.3. 限制：

不能完全取代 binary search，如果數字範圍很大(\[10^9\])，則光是建一個這麼大的陣列就會超過時間和空間限制
